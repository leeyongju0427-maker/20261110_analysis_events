# 03. 프론트엔드 구현 지침

## 1. 역할

프론트엔드는 화면 표시와 사용자 입력을 담당한다. AI 호출이나 Supabase 직접 접근은 하지 않는다.

사용 기술:
- HTML: 화면의 구조
- CSS: 화면의 디자인과 반응형 배치
- JavaScript: 입력 검증, 버튼 동작, 서버 요청, 결과 표시

## 2. HTML 구성

`index.html`에 다음 영역을 만든다.

- `header`: 브랜드 표시
- `nav`: 감성 분석 / 서비스 안내
- `main`: 페이지 제목, 설명, 분석 폼, 결과
- `form`: textarea, 글자 수, submit 버튼
- `section`: 결과 카드
- `p` 또는 `div`: 오류·상태 메시지

권장 ID:
- `sentiment-form`
- `text-input`
- `char-count`
- `analyze-button`
- `status-message`
- `result-section`
- `sentiment-label`
- `confidence-value`
- `reason-text`

실제 구현에서 ID를 바꾸면 JavaScript 선택자도 함께 변경한다.

## 3. JavaScript 동작

### 입력 글자 수
- 입력 이벤트마다 글자 수를 갱신한다.
- 최대 글자 수는 1,000자다.
- 브라우저의 `maxlength="1000"`을 사용하되 서버에서도 반드시 다시 검증한다.
- 공백만 입력한 경우 빈 입력으로 처리한다.

### 분석 요청
1. 폼 submit 이벤트를 감지한다.
2. 기본 페이지 새로고침을 막는다.
3. 앞뒤 공백을 제거한 텍스트를 검사한다.
4. 빈 입력이면 `문장을 입력해 주세요.` 표시.
5. 1,000자 초과면 길이 제한 안내.
6. 요청 중이면 중복 submit을 막는다.
7. `fetch('/api/analyze', { method: 'POST', ... })`로 JSON 요청을 보낸다.
8. 응답의 HTTP 상태와 JSON 구조를 검사한다.
9. 성공 시 결과 카드에 값을 표시한다.
10. 실패 시 서버 메시지를 그대로 무조건 신뢰하지 말고, 허용된 오류 코드에 맞는 사용자용 메시지를 표시한다.

### 안전한 화면 표시
- 사용자 텍스트, 분석 이유 등 동적 문자열은 `textContent`로 출력한다.
- 동적 문자열을 `innerHTML`에 삽입하지 않는다.
- 서버에서 받은 감성 값은 `positive`, `negative`, `neutral` 중 하나인지 확인한다.
- 신뢰도는 0~100 정수인지 확인한 뒤 표시한다.

## 4. 상태 관리

다음 상태를 명확하게 관리한다.
- `idle`: 아직 요청하지 않음
- `loading`: 분석 중
- `success`: 결과 수신
- `error`: 오류 발생

로딩 상태에서는 버튼을 비활성화한다. 요청이 끝나면 성공/실패와 관계없이 버튼을 다시 활성화한다.

## 5. API 계약

요청:

```json
{
  "text": "오늘은 정말 즐거운 하루였어."
}
```

성공 응답:

```json
{
  "ok": true,
  "result": {
    "sentiment": "positive",
    "sentimentLabel": "긍정",
    "confidence": 91,
    "reason": "즐거움과 만족을 나타내는 표현이 문장의 중심입니다."
  }
}
```

실패 응답:

```json
{
  "ok": false,
  "error": {
    "code": "INVALID_INPUT",
    "message": "분석할 문장을 입력해 주세요."
  }
}
```

## 6. 서비스 안내 영역

사이드바의 “서비스 안내”를 누르면 별도 페이지를 만들지 않고 간단한 안내 패널을 보여주거나 안내 영역으로 스크롤한다. 이 영역에는 아래 사실을 적는다.

- AI가 문장의 전반적인 감성을 추정한다.
- 풍자, 반어, 맥락이 부족한 문장은 틀릴 수 있다.
- 신뢰도는 모델의 추정값이며 보정된 확률이 아니다.
- 민감한 개인정보를 입력하지 않는 것을 권장한다.

## 7. 검증 기준

- 빈 문자열과 공백만 입력했을 때 요청하지 않는다.
- 글자 수가 정확히 1,000자인 입력은 허용한다.
- 1,001자 입력은 차단한다.
- 버튼을 빠르게 여러 번 눌러도 요청이 중복되지 않는다.
- 성공 응답의 감성·신뢰도·이유가 각 영역에 표시된다.
- 오류 응답은 페이지 새로고침 없이 표시된다.
- 모바일에서 버튼과 텍스트가 잘리지 않는다.
- 악성 HTML 문자열을 입력해도 코드로 실행되지 않고 일반 텍스트로 처리된다.
