# 02. UI 디자인 및 화면 구현 지침

## 1. 참고 이미지 해석

첨부 이미지는 다음 디자인 특징을 가진다. 이 특징을 감성 분석 서비스에 맞게 재구성한다.

- 짙은 바깥 배경 위에 흰색의 큰 둥근 패널
- 패널 상단의 얇은 헤더와 브랜드 표시
- 왼쪽 세로 메뉴와 오른쪽 메인 콘텐츠
- 본문 상단의 큰 제목 및 일러스트 영역
- 파란색 포커스 테두리의 검색 입력창
- 둥근 모서리, 얇은 회색 테두리, 넉넉한 여백
- 전체적으로 친근하고 정돈된 교육 서비스 분위기

참고 이미지의 Duolingo 로고, 이름, 카피, 캐릭터, 특정 일러스트를 복사하지 않는다. 자체 브랜드와 단순한 감성 아이콘으로 대체한다.

## 2. 화면 레이아웃

### 데스크톱 (기준 너비 1200px 이상)

1. 페이지 바깥 배경: 차콜 `#17191D` 계열.
2. 중앙 앱 패널: 흰색, 최대 너비 약 1240px, 최소 높이 90vh, 둥근 모서리 24px.
3. 헤더: 높이 약 68px, 아래쪽 연한 구분선.
   - 왼쪽: 작은 자체 브랜드 심볼 + “마음결”
   - 오른쪽: 장식용 아이콘은 최소화. 기능이 없는 아이콘은 버튼처럼 보이지 않게 한다.
4. 사이드바: 폭 약 220px.
   - “감성 분석” (기본 선택)
   - “서비스 안내”
   - 실제 기능이 없는 “기록”, “설정” 메뉴는 만들지 않는다.
5. 본문: 좌우 여백 40~56px.
   - 제목: “문장 속 감정을 읽어드려요”
   - 보조 설명: “텍스트를 입력하면 긍정, 부정, 중립으로 분석합니다.”
   - 제목 옆에는 자체 제작한 단순한 말풍선/표정 도형을 배치할 수 있다.
   - 입력창, 분석 버튼, 결과 카드 순서로 배치한다.

### 모바일 (너비 360~767px)

- 앱 패널은 화면 전체 폭을 사용하고 바깥 여백을 줄인다.
- 사이드바는 상단 가로 탭 또는 간결한 메뉴로 전환한다.
- 본문은 한 열로 배치하고 좌우 여백은 18~20px로 한다.
- 입력창과 주요 버튼은 가로 폭 100%를 사용한다.
- 결과 카드의 항목이 겹치거나 가로 스크롤이 생기지 않도록 한다.

## 3. 색상·타이포그래피

| 용도 | 권장 값 |
|---|---|
| 바깥 배경 | `#17191D` |
| 기본 본문 | `#34383F` |
| 보조 본문 | `#777E87` |
| 구분선·테두리 | `#E6E9ED` |
| 기본 파랑 | `#20A9E8` |
| 파랑 배경 | `#E5F6FF` |
| 카드 배경 | `#FFFFFF` |
| 긍정 보조색 | `#2E9D65` |
| 부정 보조색 | `#D65A5A` |
| 중립 보조색 | `#7A8492` |

- 시스템 기본 글꼴을 우선 사용한다. 한국어에서는 `Pretendard`, `Noto Sans KR`, sans-serif 순으로 지정할 수 있다.
- 제목은 굵게, 보조 문구는 낮은 대비로 표현한다.
- 감성별 색상은 보조 표현으로만 사용하고 라벨 텍스트를 항상 함께 표시한다.

## 4. 입력 영역

- 여러 줄 입력창(textarea)을 사용한다.
- placeholder: `분석하고 싶은 문장을 입력해 주세요.`
- 입력창은 흰색 또는 아주 연한 회색 배경, 1px 회색 테두리, 포커스 시 파란색 테두리.
- 아래쪽에 `0 / 1,000자` 카운터를 표시한다.
- 입력창 아래에 “개인정보나 민감한 정보는 입력하지 않는 것을 권장합니다.” 안내를 표시한다.
- 주요 버튼 문구: `감성 분석하기`
- 버튼은 파란색 계열이며 hover, focus-visible, disabled 상태를 구분한다.

## 5. 결과 카드

분석 성공 시 입력 영역 아래에 결과 카드가 나타난다.

- 카드 상단: “분석 결과”
- 가장 눈에 띄는 값: 긍정 / 부정 / 중립
- 신뢰도: 예) `신뢰도 87%`
- 분석 이유: AI가 반환한 1~3문장
- 하단 안내: “신뢰도는 AI 모델의 추정값이며 실제 감정이나 의도를 확정하지 않습니다.”

감성별 색상 예시:
- 긍정: 초록색 점/연한 초록 배경
- 부정: 붉은색 점/연한 붉은 배경
- 중립: 회색 점/연한 회색 배경

## 6. 상태별 화면

- 초기: 입력창과 버튼, 사용 안내만 표시.
- 로딩: 버튼 비활성화, 버튼 문구를 “분석 중…”으로 변경, 작은 로딩 표시.
- 성공: 결과 카드 표시.
- 오류: 입력 영역 아래에 명확한 오류 문구 표시.
- 재분석: 새 요청이 시작되면 이전 오류를 지우고 로딩 상태로 전환한다. 이전 결과는 새 결과가 오기 전까지 숨기거나 “이전 결과”임을 명확히 표시한다.

## 7. 접근성 및 완료 기준

- 모든 입력에는 label이 연결되어야 한다.
- 버튼과 메뉴는 키보드 Tab/Enter/Space로 사용할 수 있어야 한다.
- 포커스 링을 제거하지 않는다.
- 오류는 `role="alert"` 또는 적절한 live region으로 알린다.
- 모바일 360px에서 가로 스크롤이 없어야 한다.
- 브라우저 확대 200%에서도 핵심 기능을 사용할 수 있어야 한다.
- 버튼, 입력, 결과 카드가 참고 이미지의 둥근 흰색 패널/파란색 강조 분위기와 일관되어야 한다.
