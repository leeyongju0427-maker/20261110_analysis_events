# 05. Supabase 데이터베이스 및 개인정보 지침

## 1. 데이터 저장 원칙

이번 MVP에는 로그인 기능이 없으므로 사용자별 분석 기록을 제공하지 않는다. 공개 서비스에서 원문 텍스트를 저장하면 다른 사용자의 정보가 노출될 수 있고 개인정보 위험이 커진다.

따라서 Supabase는 서비스 운영 현황을 위한 **익명 집계 메타데이터 저장소**로만 사용한다.

저장하지 않는 데이터:
- 사용자가 입력한 원문
- AI가 생성한 분석 이유
- 이름, 이메일, 계정 ID
- IP 주소, 브라우저 식별 정보
- 원문을 복원할 수 있는 해시 또는 식별자

## 2. 테이블

테이블명: `analysis_events`

| 컬럼 | 타입 | 필수 | 설명 |
|---|---|---:|---|
| `id` | `bigint generated by default as identity` | 예 | 내부 이벤트 번호 |
| `created_at` | `timestamptz` | 예 | 저장 시각, 기본값 `now()` |
| `sentiment` | `text` | 예 | `positive`, `negative`, `neutral` |
| `confidence_bucket` | `text` | 예 | `0-49`, `50-69`, `70-84`, `85-100` |
| `model_name` | `text` | 아니오 | 사용한 모델명(비밀정보 아님) |

원문, 분석 이유, IP, 이메일, 세션 ID 컬럼은 만들지 않는다.

## 3. SQL 초기화

Supabase 대시보드의 SQL Editor에서 아래 SQL을 실행한다.

```sql
create table if not exists public.analysis_events (
  id bigint generated by default as identity primary key,
  created_at timestamptz not null default now(),
  sentiment text not null check (sentiment in ('positive', 'negative', 'neutral')),
  confidence_bucket text not null check (
    confidence_bucket in ('0-49', '50-69', '70-84', '85-100')
  ),
  model_name text
);

alter table public.analysis_events enable row level security;

-- 브라우저(anon key)에서 직접 읽거나 쓰는 정책은 만들지 않는다.
-- 서버의 Service Role 키를 사용하는 백엔드만 기록한다.
```

Service Role 키는 RLS를 우회할 수 있으므로 서버 코드에서만 사용하고 절대로 클라이언트에 전달하지 않는다.

## 4. 서버 저장 규칙

분석 성공 후 서버에서 아래 값만 저장한다.
- 감성 코드
- 신뢰도 구간
- 모델명

신뢰도 구간 예시:
- 0~49 → `0-49`
- 50~69 → `50-69`
- 70~84 → `70-84`
- 85~100 → `85-100`

분석 이유와 원문은 저장하지 않는다. Supabase insert가 실패해도 이미 완료된 분석 결과는 정상 반환한다. 서버에는 민감한 입력값 없이 오류 유형만 기록한다.

## 5. 접근 제어

- `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`는 서버 환경 변수에만 둔다.
- 프론트엔드에서 Supabase SDK를 초기화하지 않는다.
- anon key를 HTML/JavaScript에 넣지 않는다. 이번 MVP에서는 필요하지 않다.
- 테이블의 RLS를 활성화한다.
- 일반 공개 사용자에게 `SELECT`, `INSERT`, `UPDATE`, `DELETE` 정책을 부여하지 않는다.
- 서버에서 필요한 insert만 수행한다.

## 6. 보존 및 삭제

- MVP에서는 통계 메타데이터만 저장한다.
- 운영 목적에 필요한 기간을 정해 정기적으로 오래된 기록을 삭제한다. 기본 운영 정책은 90일 이내 보존을 권장한다.
- 실제 자동 삭제 작업은 MVP 필수 구현 범위가 아니다. 자동화하지 않았다면 “90일 자동 삭제가 구현됨”이라고 안내하지 않는다.

## 7. 검증 기준

- 분석 요청 후 Supabase에 행이 생성되는지 확인한다.
- 생성된 행에 원문, 분석 이유, IP 주소가 없는지 확인한다.
- 브라우저 개발자 도구에서 Service Role 키가 보이지 않는지 확인한다.
- anon 접근으로 테이블을 조회하거나 수정할 수 없는지 확인한다.
- Supabase 연결을 끊거나 잘못된 키를 설정해도 분석 결과 자체는 반환되는지 확인한다.
